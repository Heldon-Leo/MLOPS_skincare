# AI-Powered Skincare Routine Ingredient Checker  
## Project Report & Viva Q&A Reference

---

## 1. Problem Statement

Manual skincare ingredient checking is error-prone and inaccessible. Consumers layer 3–7 products daily but cannot easily:
- Verify whether individual ingredients serve intended functions (hydration, exfoliation, UV protection)
- Detect cross-product active conflicts (retinoids + direct acids → barrier disruption)
- Identify duplicate active ingredients that dilute efficacy or cause over-exfoliation

This project delivers an **automated, ML-powered ingredient analysis system** with a full MLOps pipeline.

## 4. Machine Learning Models

### 4.1 Product Category Classifier

| Property | Value |
|---|---|
| Task | Multi-class classification (6 skincare categories) |
| Features | TF-IDF (word N-grams) + tabular features (FeatureUnion) |
| Algorithms | Logistic Regression (baseline) vs Random Forest (production) |
| Production Gate | Accuracy >= 0.40 AND Macro-F1 >= 0.40 + inference smoke test |
| Result | RF: 54.67% accuracy, Macro-F1 0.5536 |

### 4.2 Individual Ingredient Function Classifier (NLP)

| Property | Value |
|---|---|
| Task | Multi-class classification (8 INCI functional classes) |
| Features | TF-IDF char_wb N-grams (2-4 char) |
| Algorithm | Logistic Regression (C=1.0, solver=lbfgs) |
| Fallback | "Unknown / Insufficient evidence" for low-confidence inputs |

**8 Classes:** Humectant, Emollient, Occlusive, Exfoliating agent, Antioxidant, Surfactant, Soothing / Anti-inflammatory, Sunscreen active

## 6. Key Technical Features

### Product Lookup (rapidfuzz) — Three-level matching
1. Exact: `token_sort_ratio == 100`
2. Partial: `partial_ratio >= 80`
3. Fuzzy Levenshtein: `WRatio >= 60` (handles typos)

### INCI Synonym Normalization
`ingredient_synonyms.json` maps 30+ synonym chains (Aqua->Water, Nicotinamide->Niacinamide, etc.)

### Concentration Extraction
Regex extracts inline percentages: "Niacinamide 10%" -> {name: "Niacinamide", concentration: "10%"}

### Multi-Product Conflict Status Codes

| Code | Trigger |
|---|---|
| `POTENTIAL_CONFLICT` | Matched configured incompatible pair |
| `DUPLICATE_ACTIVE` | Same active class found in 2+ products |
| `USER_AVOID_LIST_MATCH` | Ingredient on user avoid list |
| `INSUFFICIENT_INFORMATION` | No ingredient list available |
| `NO_CONFIGURED_CONFLICT_FOUND` | No configured conflicts detected |

### Packaging Label OCR
Pipeline: grayscale -> contrast boost -> Otsu threshold -> pytesseract -> graceful fallback

## 8. Viva Q&A Reference

**Q: Why Random Forest over deep learning?**
A: Dataset has ~1,472 records. Deep learning needs 10,000+. RF+TF-IDF gives interpretable results at this data scale, integrates with MLflow sklearn autologging, and both LR baseline and RF production models are compared in separate tracked runs.

**Q: How does MLflow enable model rollback?**
A: Every promoted model is logged in `model_registry.json` with version, timestamp, accuracy, F1, and run_id. `scripts/retrain.py --rollback` reads the registry, restores the previous entry to `production_model.joblib`, and records the event as a new registry entry.

**Q: How is data drift detected?**
A: `drift_monitor.py` tracks: (1) unseen ingredient rate — % of inference tokens not in training vocabulary, and (2) top-N vocabulary shift comparing sliding window against training reference distribution.

**Q: What conflicts does the rule engine cover?**
A: 5 evidence-reviewed pairs: Retinoids + direct AHAs/BHAs, Benzoyl Peroxide + Retinoids, Retinoids + Vitamin C (direct acids), Physical vs chemical sunscreen actives, Niacinamide + pure Vitamin C. Plus cross-product duplicate active class detection.

**Q: Why char N-gram TF-IDF for ingredient names?**
A: Morphological suffixes (-ol, -ane, -yl, -acid) correlate strongly with chemical class. Char N-grams are robust to typos and novel INCI names not seen during training. Trade-off: semantics may not always align with morphology.

**Q: Why Pydantic v2?**
A: FastAPI 0.100+ integrates Pydantic v2 natively. 5-50x faster validation vs v1, strict mode for API contract enforcement, all schemas validated before reaching business logic.
